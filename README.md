> 明牌列阵，胜负在出手之间。

一款 3v3 明牌回合制战棋。双方各带十人编队，三人同时上阵，全员按**速度**轮流出手；每名武将有两个带**冷却**的主动战法，外加一个**不需施展的天赋**——可能常驻加成，也可能在阵亡、受伤、击杀、友军倒下时自动触发；有人倒下，后援立刻顶替。除了拼面板，还要拼**控制、增益、减益、持续伤害**的叠加与化解，以及**触发时机的预判**——沉默住对方的爆发、嘲讽住对方的刺客、用净化解掉眩晕，甚至故意送掉一人来引爆友军的天赋。没有随机数，输赢都能复盘。

## 玩法

- **十人编队，三人上阵**：布阵时从十人中挑 3 名首发，其余按编队顺序作后援。
- **五维属性**：生命、攻击、防御、智力、速度。速度决定出手顺序；速度相同则我方先手。
- **每回合每人行动一次**：普攻、技能、防御三选一。
  - **普攻**：攻击 × 100% 的物理伤害，需点选目标；**被缴械时无法普攻**。
  - **防御**：防御 +50%，持续 1 回合，用来扛过对方的关键技能。
  - **技能**：每人两个专属主动战法，冷却 2–4 回合，按类型分为兵刃 / 谋略 / 防御 / 统御 / 身法。单体技能要先点敌人，群体/自身技能直接释放；**被沉默时无法施展技能**。
  - **天赋**：每人一个被动或触发技能，不占行动。触发时机包括回合开始、回合结束、受到伤害、造成伤害、击杀、阵亡、友军阵亡、敌军阵亡、被选为目标、我方或敌方做出某种行动、生命首次跌破阈值等；天赋同样有内置冷却，部分天赋每场只触发一次。
  - **状态**：控制、增益、减益、护盾、持续伤害与回复都会显示为武将卡片左上角的小标签（如 `默`、`缴`、`嘲`、`盾 23`、`毒 10`）。具体数值和剩余回合数在悬停提示里。
- **倒下换将**：场上一人阵亡，后援按顺序补位，直到十人全部倒下。
- **点按查看**：场上只显示姓名、血条与状态标签；点按任意武将卡会打开详报，展示完整五维、两个战法与天赋。状态标签可悬停查看数值与剩余回合。
- **回合上限**：30 回合仍未分胜负时，按全队剩余兵力比例判定；比例与存活人数都相同则我方胜。

## 界面

全站只有一个入口：根目录的 `index.html`。它保留将星谱的深色鎏金视觉，把战棋的完整数据与规则接进同一套卡片和动线里：

- **点将台**：左侧主将卡与「出征」入口，右侧六张点将卡；可按魏 / 蜀 / 吴 / 群筛选、翻页换一批，点卡片即切换主将，主将卡上的「详报」打开完整数据。
- **布阵**：从十人编队中依次点选三名首发，右上角「开战」在选满后启用；其余七人按编队顺序候补。
- **战场**：敌军与我军各三张场上卡、七张后援卡；行动中的武将有金色「行动」标记，敌方目标有「目标」标记；顶部出手顺序、回合数与战报，底部军令栏提供普攻、两个战法、防御、详报与战报。
- **武将图鉴**：六十名武将按势力分组，可按姓名、称号、势力、定位、标签与战法文案搜索；每张卡打开后可查看生命 / 攻击 / 防御 / 智力 / 速度五维、两个主动战法（含类型、冷却、说明）与一个天赋。
- **详情与战报**：任意武将卡可打开详报；战报抽屉逐条记录伤害、治疗、护盾、状态与天赋触发；结算弹层显示大捷 / 败北、评价、回合、存活、后援与总伤害。

`ui-demo/` 保留为早期的静态视觉参考，已不再作为入口，也不参与构建。正式入口、样式与逻辑都在 `index.html` 与 `src/web/`。

## 战斗规则

### 伤害结算

```
物理伤害 = max(1, round(攻击 × 倍率 − 防御 × 0.4 × (1 − 破甲)))
法术伤害 = max(1, round(智力 × 倍率 − 目标智力 × 0.3))
最终伤害 = max(1, round(基础伤害 × (1 − 虚弱) × (1 + 易伤)))
```

- 有效属性 = 基础属性 × (1 + 增益% − 减益%)，只影响出手顺序与伤害计算，不改基础面板。
- 护盾先吸收伤害，溢出部分才扣生命；荆棘会把受到的伤害按比例反弹给攻击者。
- 治疗先经过禁疗削减；吸血按最终造成的伤害回复自身。

### 状态一览

| 分类 | 状态 | 效果 |
| --- | --- | --- |
| 控制 | 眩晕 | 跳过该次行动 |
| | 沉默 | 不能施展技能，仍可普攻 |
| | 缴械 | 不能普攻，仍可施展技能 |
| | 嘲讽 | 单体普攻与单体技能只能指向嘲讽者；嘲讽者倒下后立刻失效 |
| 持续 | 灼烧 / 中毒 | 行动开始时掉血（固定点数或最大生命百分比） |
| | 回春 | 行动开始时回复生命 |
| | 护盾 | 吸收伤害，先于生命扣除 |
| | 吸血 | 造成伤害的一定比例回复自身 |
| | 禁疗 | 受到的治疗量降低 |
| 增伤减伤 | 易伤 | 受到的伤害提升 |
| | 虚弱 | 造成的伤害降低 |
| | 反击 | 受到普攻时立刻以一定比例的攻击还击 |
| | 荆棘 | 反弹所受伤害的一部分给攻击者 |
| 属性 | 增益 / 减益 | 按百分比修改攻击、防御、智力或速度 |

- 灼烧、中毒、回春在持有者**行动开始时**结算；其余状态在持有者**行动结束时**统一扣 1 回合。刚获得的状态当回合不扣，所以「2 回合」实际会生效两次。
- 眩晕在轮到该单位时直接跳过行动，并消耗 1 回合。
- **净化**只解除负面状态，**驱散**只移除增益与护盾，各司其职。多个效果可以写在同一个技能里，每个效果还能单独指定目标（例如对敌群攻的同时给自己回春）。
- 结算完全确定：同 seed + 同一串操作 = 同一结果，输掉可以完整复盘。

### 开发与验证

`src/web/` 的四个屏幕支持调试深链，直接落到目标界面，不必每次从头点：

```text
/?screen=home
/?screen=codex
/?screen=deploy&seed=42
/?screen=battle&seed=42&starters=P0,P1,P2&fast=1
/?screen=result&outcome=victory&round=9&damage=1234&fast=1
```

- `seed` 固定随机种子；`starters` 可写 `P0,P1,P2` 或武将 id。
- `outcome` 为 `victory` / `defeat`，`round`、`damage` 写入结算。
- `fast=1` 关闭动画与时序，适合截图和自动化。
- 控制台还可用 `jiangxing.debug.finish('victory', 9, 777)`、`jiangxing.debug.go('codex')`、`jiangxing.debug.newRun(42)`。

浏览器冒烟检查不依赖 Playwright / Puppeteer：

```bash
npm run qa
```

脚本会用 Vite 的 Node API 起临时服务器，驱动本机 Chrome / Edge（非标准路径用 `CHROME_PATH` 指定），在 `1440×900` 与 `390×844` 下检查四个屏幕、搜索、选人、战场与结算，断言无控制台错误、无失败请求、无横向溢出，并输出 10 张截图（含武将详报）与 `.qa/report.json`。`.qa/` 已加入 `.gitignore`。Node 需 22+（内置 WebSocket）。

更细的协作约定、验证分层、断点与踩坑记录见 [`CLAUDE.md`](CLAUDE.md)。

**生产**：`npm run build && npm run server`，访问 `http://127.0.0.1:8787/`。Node 服务同时提供 `dist/` 静态文件与 `/api`，并对 HTML 设置 CSP 等安全响应头。

**环境变量**：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址；只在本机用时设为 `127.0.0.1` |
| `DB_PATH` | `server/data/accounts.db` | SQLite 数据库路径，目录会自动创建 |
| `ALLOWED_ORIGINS` | 无 | 额外允许的跨域来源，逗号分隔；同源与 localhost 之外默认拒绝 |
| `VITE_API_BASE` | `/api` | 前端请求 API 的前缀，构建时注入 |

账号数据默认落在 `server/data/accounts.db`（已加入 `.gitignore`）。**GitHub Pages 只托管静态文件，跑不了 Node 服务与数据库**；要用账号功能，需把仓库部署到能运行 Node 24 的主机，或直接在本机运行 `npm run server`。

## 安卓 APK

游戏通过 Capacitor 打包成安卓应用，Web 资源与规则引擎全部打进 APK，离线可玩。

```bash
npm run android:apk       # 构建网页 + 同步 + 编译 debug APK
```

构建需要 JDK 21、Android SDK Platform 36 与 Build-Tools 36.0.0；请先让 `JAVA_HOME` 指向 JDK 21、`ANDROID_HOME` 指向 SDK 目录。产物在 `android/app/build/outputs/apk/debug/app-debug.apk`，可直接安装到 Android 7.0（API 24）及以上设备。改完界面或数据后运行 `npm run android:sync` 同步到安卓工程。

**APK 内的账号**：不连接 `server/`，账号与密码哈希保存在设备本地的 WebView 存储中，密码使用 PBKDF2-SHA256（21 万次迭代）加随机盐；卸载应用会清除账号。网页版仍使用 Node + SQLite 的服务端账号体系，两者互不影响。

### 账号与数据库

- 表结构：`users`（用户名、昵称、密码哈希、注册/最后登录时间）与 `sessions`（令牌哈希、用户、过期时间）；外键级联删除，WAL 模式。
- 密码用 Node 内置 `crypto.scrypt`（N=16384, r=8, p=1）加每用户随机盐，只存 `scrypt$...` 哈希，校验用 `timingSafeEqual`；用户不存在时也做一次等价的兜底校验，避免按耗时枚举用户名。
- 会话令牌为 32 字节随机值，数据库只存其 SHA-256；Cookie 名为 `zq_session`，`HttpOnly`、`SameSite=Lax`、30 天过期，HTTPS 下自动加 `Secure`。
- 非 GET/HEAD 请求校验 `Origin`；登录按 IP + 用户名限流（10 分钟 8 次）；请求体只收 JSON 且上限 16 KB；SQL 全部走参数化查询；静态文件做路径穿越检查。
- 修改密码会删除该用户的其他会话，只保留当前设备。

**核心原则**：逻辑与表现分离。`core` 不引用任何 DOM，CLI 与 Web 共用同一套规则。

## 数据驱动

- `data/generals.json`：60 名武将的生命/攻防/智力/速度、所属势力（魏 / 蜀 / 吴 / 群）、两个主动技能 id 与一个天赋 id。
- `data/skills.json`：180 个技能，含类型、触发时机、冷却、目标类型与效果序列。效果类型覆盖 `damage / heal / buff / debuff / shield / burn / poison / regen / stun / silence / disarm / taunt / vulnerable / weaken / healBlock / lifesteal / counter / thorns / cleanse / dispel / loseHp / if / cooldown`。
- `data/config.json`：编队人数、上场人数、回合上限。

想加一名武将，只需在 `generals.json` 里补一条，再在 `skills.json` 里配技能；引擎会自动加载。技能类型用 `type` 标注（`blade / strategy / defense / command / movement / passive`），触发时机用 `trigger` 标注：

- `active`：主动战法，放进 `skills`，行动时施展。
- `passive`：常驻，用 `aura` 提供属性光环（可作用于自身 / 友军 / 敌军）。
- 其余时机：`turnStart / turnEnd / roundStart / roundEnd / attack / defend / cast / dealDamage / takeDamage / heal / kill / death / allyDeath / enemyDeath / targeted / actionUsed / hpBelow`，放进 `talents`，由引擎在对应事件自动检查。

触发技能可用 `when` 限定条件（敌我人数、回合数、生命阈值、身上的状态、是否快过所有敌人等），用 `by` 限定行为者（`self / ally / enemy / any`），用 `action` 与 `skillType` 限定具体行为或战法类型，用 `maxTriggers` 限制每场次数。效果里新增了 `if`（按条件走 `then` / `else` 分支）与 `cooldown`（缩短或重置冷却）；每个效果还能用 `target` 单独指定作用对象，触发时还可以用 `source`（事件来源）与 `triggerTarget`（事件目标）指向触发者或受害者的对象。所以「友军阵亡时给其余友军护盾并缩短冷却」这类复合逻辑不用改代码，直接写 JSON 就行。

## 平衡

`npm run sim` 让双方使用同一套 AI、按同一规则挑选首发，统计 300 局：

```
我军胜 53.0%  败 47.0%
平均 14.5 回合，最长 30 回合
```

胜率接近五五开，说明数值大致对称；平均 15 回合、最长触到 30 回合上限，说明对局有收束，不会无限拖下去。加入控制与增减益后，AI 对局里每局都会出现嘲讽、沉默、缴械、中毒、荆棘、护盾等交换，节奏没有因为状态变多而拖长。真人玩家在技能时机、目标选择上有 AI 没有的空间，这也是操作性所在。

单元测试覆盖伤害公式、冷却、换将、判定，以及沉默 / 缴械 / 嘲讽 / 易伤 / 虚弱 / 荆棘 / 反击 / 中毒 / 回春 / 净化 / 驱散等状态机制，另有天赋触发（被动光环、受伤、阵亡、击杀、生命阈值）、主动技能拒绝施展、冷却缩短、自损换增益与高生命目标增伤等用例；账号部分覆盖用户名 / 密码 / 昵称校验、加盐哈希、错误密码拒绝与兜底校验；渲染部分校验卡面状态折叠、六十名武将的五维 / 战法 / 天赋结构，以及场景立绘覆盖（`npm test`，45 项：战斗 31 + 账号 7 + 渲染 7）。
