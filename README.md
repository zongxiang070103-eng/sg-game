# 战棋

> 明牌列阵，胜负在出手之间。

一款 3v3 明牌回合制战棋。双方各带十人编队，三人同时上阵，全员按**速度**轮流出手；每名武将有两个带**冷却**的专属技能；有人倒下，后援立刻顶替。除了拼面板，还要拼**控制、增益、减益、持续伤害**的叠加与化解——沉默住对方的爆发、嘲讽住对方的刺客、用净化解掉眩晕，胜负常常在技能交换之间就分出来了。没有随机数，输赢都能复盘。

## 玩法

- **十人编队，三人上阵**：布阵时从十人中挑 3 名首发，其余按编队顺序作后援。
- **五维属性**：生命、攻击、防御、智力、速度。速度决定出手顺序；速度相同则我方先手。
- **每回合每人行动一次**：普攻、技能、防御三选一。
  - **普攻**：攻击 × 100% 的物理伤害，需点选目标；**被缴械时无法普攻**。
  - **防御**：防御 +50%，持续 1 回合，用来扛过对方的关键技能。
  - **技能**：每人两个专属技能，冷却 2–4 回合。单体技能要先点敌人，群体/自身技能直接释放；**被沉默时无法施展技能**。
  - **状态**：控制、增益、减益、护盾、持续伤害与回复都会显示为武将卡片下方的小标签（如 `默`、`缴`、`嘲`、`盾 23`、`毒 10`）。具体数值和剩余回合数在悬停提示里。
- **倒下换将**：场上一人阵亡，后援按顺序补位，直到十人全部倒下。
- **信息藏在悬停里**：场上只显示姓名、血条与状态标签，把鼠标停在武将上才展开完整属性、技能说明与冷却、当前状态的详细说明；触屏上点按卡片同样会弹出详情。
- **回合上限**：30 回合仍未分胜负时，按全队剩余兵力比例判定；比例与存活人数都相同则我方胜。

## 界面

界面按手游的「主城 → 布阵 → 战斗 → 结算」动线组织，深色鎏金底，魏蓝、蜀绿、吴红三色区分势力：

- **主城**：出征入口、玩法速览与底部导航；桌面端纵向居中，窄屏下内容自然堆叠滚动。
- **武将图鉴**：二十名武将按魏 / 蜀 / 吴筛选，卡片展示姓氏字与称号，点开查看五维、势力与两个技能的完整说明。
- **成长**：成长系统的入口已留位，列出等级与战功、技能强化、装备、缘分四项规划，标注「筹备中」。
- **布阵**：上方三个首发位，下方十人候选；悬停（触屏点按）在右侧展开武将详情，选满三人后开始战斗，也可以「换一批」重开。
- **战斗**：卡片化战场分为敌军 / 我军两侧，行动中的武将有金色高亮与「行动」标记；状态以小标签显示，顶部可开关战报，底部行动栏提供普攻、技能、防御与取消；点击任意武将可查看属性、技能冷却与状态详情。
- **结算**：显示大捷 / 败北、双方存活人数与本局种子，可直接再战或返回主城。

另有一套独立的视觉概念稿在 [`ui-demo/`](ui-demo/)，用全身立绘卡牌重做了「点将 → 战场 → 结算」的界面，可直接双击打开。它只演示视觉与交互，战斗数值经过简化，不是正式的确定性引擎。

## 战斗规则

### 伤害结算

```
物理伤害 = max(1, round(攻击 × 倍率 − 防御 × 0.4 × (1 − 破甲)))
法术伤害 = max(1, round(智力 × 倍率 − 目标智力 × 0.3))
最终伤害 = max(1, round(基础伤害 × (1 − 虚弱) × (1 + 易伤)))
```

- 有效属性 = 基础属性 × (1 + 增益% − 减益%)，只影响出手顺序与伤害计算，不改基础面板。
- 护盾先吸收伤害，溢出部分才扣生命；荆棘会把受到的伤害按比例反弹给攻击者。
- 治疗先经过禁疗削减；吸血按最终造成的伤害回复自身。

### 状态一览

| 分类 | 状态 | 效果 |
| --- | --- | --- |
| 控制 | 眩晕 | 跳过该次行动 |
| | 沉默 | 不能施展技能，仍可普攻 |
| | 缴械 | 不能普攻，仍可施展技能 |
| | 嘲讽 | 单体普攻与单体技能只能指向嘲讽者；嘲讽者倒下后立刻失效 |
| 持续 | 灼烧 / 中毒 | 行动开始时掉血（固定点数或最大生命百分比） |
| | 回春 | 行动开始时回复生命 |
| | 护盾 | 吸收伤害，先于生命扣除 |
| | 吸血 | 造成伤害的一定比例回复自身 |
| | 禁疗 | 受到的治疗量降低 |
| 增伤减伤 | 易伤 | 受到的伤害提升 |
| | 虚弱 | 造成的伤害降低 |
| | 反击 | 受到普攻时立刻以一定比例的攻击还击 |
| | 荆棘 | 反弹所受伤害的一部分给攻击者 |
| 属性 | 增益 / 减益 | 按百分比修改攻击、防御、智力或速度 |

- 灼烧、中毒、回春在持有者**行动开始时**结算；其余状态在持有者**行动结束时**统一扣 1 回合。刚获得的状态当回合不扣，所以「2 回合」实际会生效两次。
- 眩晕在轮到该单位时直接跳过行动，并消耗 1 回合。
- **净化**只解除负面状态，**驱散**只移除增益与护盾，各司其职。多个效果可以写在同一个技能里，每个效果还能单独指定目标（例如对敌群攻的同时给自己回春）。
- 结算完全确定：同 seed + 同一串操作 = 同一结果，输掉可以完整复盘。

## 运行

```bash
npm install
npm run dev                 # 本地试玩
npm run sim                 # 双方同 AI 跑 300 局，查看平衡与节奏
npm run sim -- --seed 42    # 打印指定种子的完整一战
npm test                    # 单元测试
npm run build               # 构建静态站点
```

构建产物在 `dist/`，可直接部署到 GitHub Pages（已配置相对路径）。

## 项目结构

```
src/core/     纯逻辑，不依赖 DOM
  battle.ts     战斗引擎：出手队列、伤害、状态、冷却、换将、判定
  status.ts     状态的分类、标签与悬停说明（引擎与界面共用）
  ai.ts         启发式 AI：普攻与技能的估值
  data.ts       读取并校验 data/ 下的武将、技能
  types.ts      类型定义
  config.ts     编队人数、上场人数、回合上限
  rng.ts        种子随机，整局可复现
src/cli/      无头模拟器（平衡调参用）
src/web/      浏览器界面（主城、图鉴、布阵、战斗、悬浮提示）
ui-demo/      独立的卡牌视觉概念稿（静态，无构建）
data/         配置、武将、技能（可 mod）
tests/        单元测试
```

**核心原则**：逻辑与表现分离。`core` 不引用任何 DOM，CLI 与 Web 共用同一套规则。

## 数据驱动

- `data/generals.json`：20 名武将的生命/攻防/智力/速度、所属势力（魏 / 蜀 / 吴）与两个技能 id。
- `data/skills.json`：40 个技能，含冷却、目标类型与效果序列。效果类型覆盖 `damage / heal / buff / debuff / shield / burn / poison / regen / stun / silence / disarm / taunt / vulnerable / weaken / healBlock / lifesteal / counter / thorns / cleanse / dispel`。
- `data/config.json`：编队人数、上场人数、回合上限。

想加一名武将，只需在 `generals.json` 里补一条，再在 `skills.json` 里配技能；引擎会自动加载。技能目标有 `enemy / allEnemies / lowestEnemy / strongestEnemy / self / lowestAlly / allAllies`，还支持 `targetHpBelow`、`allyFieldAtMost` 等条件；每个效果还能用 `target` 单独指定作用对象，所以「打敌人顺便给自己回血」这类复合技能不用改代码，直接写 JSON 就行。

## 平衡

`npm run sim` 让双方使用同一套 AI、按同一规则挑选首发，统计 300 局：

```
我军胜 49.3%  败 50.7%
平均 15.2 回合，最长 30 回合
```

胜率接近五五开，说明数值大致对称；平均 15 回合、最长触到 30 回合上限，说明对局有收束，不会无限拖下去。加入控制与增减益后，AI 对局里每局都会出现嘲讽、沉默、缴械、中毒、荆棘、护盾等交换，节奏没有因为状态变多而拖长。真人玩家在技能时机、目标选择上有 AI 没有的空间，这也是操作性所在。

单元测试覆盖伤害公式、冷却、换将、判定，以及沉默 / 缴械 / 嘲讽 / 易伤 / 虚弱 / 荆棘 / 反击 / 中毒 / 回春 / 净化 / 驱散等状态机制（`npm test`，21 项）。
