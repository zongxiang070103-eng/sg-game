# 架构说明

## 一句话概括

「将星谱」是一个**单页、离线可玩**的 3v3 明牌回合制卡牌战棋。规则核心与 DOM 解耦，六十名武将和一百八十个战法由 JSON 数据驱动，界面只负责展示与交互。

## 分层

```
┌──────────────────────────────────────────────┐
│ 浏览器入口 index.html + src/web/*             │
│ 点将台 / 图鉴 / 布阵 / 战场 / 战报 / 结算      │
└──────────────────────┬───────────────────────┘
                       │ 只调用核心 API，不反向依赖
┌──────────────────────▼───────────────────────┐
│ 规则核心 src/core/*                           │
│ 战斗状态机、伤害结算、技能、状态、AI、随机源   │
└──────────────────────┬───────────────────────┘
                       │ 只读
┌──────────────────────▼───────────────────────┐
│ 数据 data/*.json                              │
│ generals / skills / config / ui-meta          │
└──────────────────────────────────────────────┘

可选：server/*（账号 API）  android/*（Capacitor 壳）
```

### `src/core/` —— 规则核心

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 武将、技能、状态、事件、战斗快照的类型定义 |
| `battle.ts` | 战斗状态机：出手顺序、行动、伤害、换将、回合上限、战报事件 |
| `skill.ts` | 主动技能与天赋的触发时机、目标筛选、冷却 |
| `status.ts` | 控制、增益、减益、持续伤害、护盾的叠加与结算 |
| `ai.ts` | 双方自动行动的策略，用于模拟与 QA |
| `data.ts` | 读取并校验 `data/*.json`，建立索引 |
| `rng.ts` | 可注入的伪随机源，模拟时可固定种子 |
| `config.ts` | 全局数值常量 |

核心层**不依赖 DOM、浏览器 API 或网络**，因此可以直接在 Node 中跑单元测试、AI 模拟和批量平衡分析。

### `src/web/` —— 界面层

| 文件 | 职责 |
| --- | --- |
| `main.ts` | 入口：加载数据、挂载路由与全局事件 |
| `home.ts` | 点将台：主将展示、势力筛选、翻页 |
| `codex.ts` | 武将图鉴：搜索、分组、详情 |
| `battle.ts` | 布阵、战场、军令栏、目标选择、结算 |
| `cards.ts` | 卡面渲染：立绘回退链、状态标签、姓名与血条 |
| `store.ts` | 本地进度、设置与编队的持久化 |
| `deeplink.ts` / `url.ts` | 查询串与 hash 深链，便于 QA 直达指定屏幕 |
| `fx.ts` / `audio.ts` | 轻量动效与音效，均可关闭 |
| `account.ts` | 可选账号 API 客户端，不参与单页游戏主流程 |
| `style.css` / `codex.css` / `merged.css` | 深色鎏金视觉、纸卷图鉴、窄屏适配 |

界面层只通过核心层暴露的函数推进战斗，不直接改写战斗状态。卡面图源有一条明确的回退链：

```
src/assets/portraits/<id>.webp   （水墨场景，满铺）
        ↓ 缺失
src/assets/cards/<id>.png        （透明全身像）
        ↓ 缺失
src/assets/codex/<id>-plate.webp （古版画图版）
        ↓ 缺失
内置 SVG                          （兜底）
```

### `data/` —— 内容数据

- `generals.json`：六十名武将的五维、势力、定位、立绘 id。
- `skills.json`：一百八十个主动战法与六十个天赋的文案、数值、冷却、触发时机。
- `config.json`：战斗全局参数。
- `ui-meta.json`：界面文案、势力配色等展示元数据。

数据与代码分离，新增武将或调整数值不需要改核心逻辑；测试会校验引用完整性与立绘覆盖率。

### 可选服务与壳

- `server/`：Node 内置 `http` + `node:sqlite` 的账号服务，提供注册、登录、资料、改密、退出。密码使用 scrypt 加盐哈希，会话使用 `HttpOnly` Cookie。不部署时单页游戏完全不受影响。
- `android/`：Capacitor 壳，Web 资源打包进 APK，离线可玩；设备本地账号使用 PBKDF2。
- `scripts/qa.mjs`：起临时 Vite 服务器，驱动本机 Chrome / Edge，在桌面与手机两个宽度跑完整流程，断言无控制台错误、无失败请求、无横向溢出，并输出截图与报告。
- `src/cli/sim.ts`：双方 AI 批量对局，用于观察胜率、回合数与技能使用分布。

## 一次行动的调用链

```
玩家点击「烈焰破阵」
  → src/web/battle.ts 校验可选目标并高亮
  → core/battle.ts performAction({ type: 'skill', skillId, targetId })
      → 扣除冷却、结算伤害/治疗/护盾
      → 触发受伤、击杀、阵亡、友军阵亡等事件
      → core/skill.ts 逐个检查天赋触发条件
      → core/status.ts 叠加或驱散状态
      → 推进到下一个有效行动者，必要时换将
      → 返回新的战斗快照与战报条目
  → 界面按快照重绘卡面、状态标签、出手顺序与战报
```

## 扩展点

- **新增武将**：在 `data/generals.json` 与 `data/skills.json` 添加条目，补一张场景立绘，跑 `npm test`。
- **新增状态**：在 `src/core/types.ts` 定义，`status.ts` 实现叠加/结算，`cards.ts` 增加标签样式，补单元测试。
- **新增界面**：在 `src/web/` 新建模块，通过深链注册屏幕；不要绕过核心层直接修改战斗对象。
- **新增平台**：复用 `dist/` 静态产物；`vite.config.ts` 的 `base: './'` 保证相对路径，可直接部署到 GitHub Pages、静态托管或 Capacitor。

## 质量保障

| 层级 | 手段 | 规模 |
| --- | --- | --- |
| 类型 | `tsc --noEmit`（strict） | 全量 |
| 单元测试 | Vitest：伤害、冷却、换将、状态、天赋、账号、渲染 | 45 项 |
| 平衡 | `npm run sim` 双方 AI 批量对局 | 300 局/次 |
| 端到端 | `npm run qa` 无头浏览器 + 截图 + 断言 | 2 个宽度、10 张截图 |
| 构建 | `npm run build`（类型检查 + Vite） | 产物 `dist/` |
| 持续集成 | GitHub Actions：typecheck / test / build | 每次 push 与 PR |

## 设计取舍

- **无随机数**：战斗不掷骰，伤害与触发时机确定，输赢可复盘；模拟时只用固定种子驱动 AI 选择。
- **数据驱动**：武将与技能是内容而不是代码，便于社区贡献与平衡调整。
- **单页无后端**：打开 `index.html` 即可玩，降低部署与评审成本；账号服务作为可选项独立演进。
- **核心与界面解耦**：规则可在 Node 中测试与模拟，界面可以替换而不动数值。
